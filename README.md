# Практическая работа: HTTP и HTTPS на Ubuntu Server

В этой работе вы создадите сервер Ubuntu в VirtualBox, установите Nginx, разместите собственную HTML-страницу и откроете её в браузере Windows.

Сначала сайт будет работать по обычному HTTP. Затем вы создадите сертификат, включите HTTPS и настроите автоматический переход с HTTP на HTTPS.

В результате должны работать два адреса:

```text
http://192.168.56.101
https://192.168.56.101
```

При открытии первого адреса браузер должен автоматически перейти на второй.

> `192.168.56.101` — адрес из примера. Используйте IP-адрес, который получила ваша Ubuntu.

## Что мы создаём

Для работы нужна только одна виртуальная машина с Ubuntu Server.

```text
┌──────────────────────────────┐
│ Windows 10 или Windows 11    │
│                              │
│ Браузер и SSH-клиент         │
│              │               │
│              ▼               │
│  ┌────────────────────────┐  │
│  │ VirtualBox             │  │
│  │ Ubuntu Server          │  │
│  │ IP: 192.168.56.101     │  │
│  │ SSH:   порт 22         │  │
│  │ HTTP:  порт 80         │  │
│  │ HTTPS: порт 443        │  │
│  └────────────────────────┘  │
└──────────────────────────────┘
```

Ubuntu будет сервером. Windows будет клиентом: с Windows мы подключимся к Ubuntu и откроем сайт.

## Что такое сервер и клиент

**Сервер** — программа или компьютер, который ожидает запросы и отвечает на них.

**Клиент** — программа, которая отправляет запрос серверу.

В этой работе:

- Nginx на Ubuntu — веб-сервер;
- браузер на Windows — клиент;
- служба SSH на Ubuntu — SSH-сервер;
- команда `ssh` в Windows — SSH-клиент.

Когда вы вводите адрес сайта, браузер отправляет запрос Nginx. Nginx находит HTML-файл и возвращает его браузеру.

## Что такое порт

На одном сервере одновременно могут работать разные сетевые программы. Порт помогает операционной системе понять, какой программе предназначено подключение.

| Порт | Протокол | Для чего используется |
| --- | --- | --- |
| `22` | SSH | Удалённое управление сервером |
| `80` | HTTP | Обычный веб-сайт без шифрования |
| `443` | HTTPS | Веб-сайт с шифрованием |

IP-адрес указывает на компьютер, а порт — на программу внутри этого компьютера.

```text
192.168.56.101:22  → SSH
192.168.56.101:80  → HTTP
192.168.56.101:443 → HTTPS
```

В адресе сайта стандартные порты обычно не пишут. Браузер сам понимает, что для HTTP нужен порт `80`, а для HTTPS — `443`.

## Что такое SSH

SSH — протокол безопасного удалённого управления сервером.

Через SSH можно:

- выполнять команды на другом компьютере;
- устанавливать программы;
- изменять настройки;
- создавать и редактировать файлы;
- перезапускать службы.

Подключение выполняется командой:

```bash
ssh имя_пользователя@IP_адрес
```

Например:

```bash
ssh student@192.168.56.101
```

Команды после подключения выполняются на Ubuntu, хотя вводите вы их в окне Windows.

SSH шифрует передаваемые данные, включая пароль. Посторонний участник сети не должен увидеть команды и пароль в открытом виде.

## Что такое HTTP

HTTP — протокол, по которому браузер и веб-сервер обмениваются данными.

Упрощённо открытие страницы выглядит так:

```text
Браузер → «Отдай главную страницу» → Nginx
Браузер ← HTML-файл             ← Nginx
```

HTTP определяет:

- как выглядит запрос браузера;
- как выглядит ответ сервера;
- какие заголовки передаются;
- какой код состояния возвращается;
- какие данные находятся в ответе.

Примеры кодов состояния:

| Код | Значение |
| --- | --- |
| `200` | Запрос выполнен успешно |
| `301` | Страница перенесена на другой адрес |
| `404` | Страница не найдена |
| `500` | Ошибка на сервере |

Главная проблема HTTP — данные передаются без шифрования. Если пользователь вводит логин, пароль или другую важную информацию, её нельзя безопасно передавать по обычному HTTP.

## Что такое HTTPS

HTTPS — это HTTP, работающий внутри защищённого TLS-соединения.

```text
HTTPS = HTTP + TLS
```

HTTPS решает три основные задачи:

1. **Шифрование.** Посторонний участник сети не должен прочитать передаваемые данные.
2. **Целостность.** Данные не должны быть незаметно изменены во время передачи.
3. **Проверка сервера.** Сертификат помогает подтвердить, к какому серверу подключился пользователь.

Перед передачей страницы браузер и сервер договариваются о защищённом соединении. После этого HTTP-запросы и ответы передаются в зашифрованном виде.

HTTPS не означает, что сам сайт честный или не содержит вирусов. Он означает, что соединение между браузером и сервером защищено, а сертификат прошёл определённую проверку.

## Что такое SSL-сертификат

Сейчас для HTTPS используется протокол TLS, но сертификаты часто по привычке называют SSL-сертификатами.

Сертификат содержит:

- сведения о владельце;
- адрес, для которого он выпущен;
- срок действия;
- открытый ключ;
- цифровую подпись центра сертификации.

Обычные публичные сайты получают сертификаты у доверенных центров сертификации. Браузеры доверяют таким центрам и не показывают предупреждение.

В этой работе домена нет, а сервер работает по локальному IP-адресу. Поэтому мы создадим **самоподписанный сертификат**.

Самоподписанный сертификат тоже позволяет шифровать соединение, но браузер не знает и не доверяет тому, кто его создал. Поэтому при первом открытии страницы появится предупреждение. Для учебного локального сервера это ожидаемое поведение.

## Шаг 1. Создайте сеть VirtualBox

Ubuntu должна одновременно:

- получать интернет для установки программ;
- быть доступной с Windows по отдельному IP-адресу.

Для этого используем два адаптера:

| Адаптер | Режим | Назначение |
| --- | --- | --- |
| Адаптер 1 | NAT | Доступ Ubuntu в интернет |
| Адаптер 2 | Виртуальный адаптер хоста | Соединение Windows и Ubuntu |

Откройте VirtualBox.

1. В левой части окна выберите **Инструменты**.
2. Откройте раздел **Сеть**.
3. Перейдите на вкладку с виртуальными сетями хоста. В разных версиях она может называться **Host-only Networks** или **Сети только для хоста**.
4. Если список пустой, нажмите **Создать**.
5. Выберите созданную сеть.
6. Убедитесь, что IPv4-адрес адаптера равен `192.168.56.1`.
7. Маска сети должна быть `255.255.255.0`.

Адрес `192.168.56.1` будет принадлежать Windows. Ubuntu автоматически получит другой адрес из этой сети, например `192.168.56.101`.

> Если сеть `192.168.56.0/24` уже используется, VirtualBox может создать другую подсеть. Во всех дальнейших командах используйте настоящий адрес своей Ubuntu.

## Шаг 2. Создайте виртуальную машину

1. В главном окне VirtualBox нажмите **Создать**.
2. В поле имени напишите `Ubuntu HTTPS Server`.
3. В поле ISO-образа выберите образ Ubuntu Server.
4. Тип системы должен определиться как **Linux**.
5. Версия — **Ubuntu (64-bit)**.
6. Выделите не менее `2048 МБ` оперативной памяти.
7. Выделите `2` процессора, если компьютер это позволяет.
8. Создайте новый виртуальный диск размером не менее `20 ГБ`.
9. Завершите создание виртуальной машины.

Если VirtualBox предлагает автоматическую установку, можно отключить её и пройти обычную установку самостоятельно.

## Шаг 3. Установите Ubuntu Server

Запустите виртуальную машину и следуйте установщику Ubuntu.

1. Выберите язык установщика.
2. Выберите раскладку клавиатуры.
3. Оставьте обычный вариант установки Ubuntu Server.
4. Сетевые настройки во время установки можно оставить автоматическими.
5. Используйте весь виртуальный диск. Это затронет только созданный виртуальный диск, а не диск Windows.
6. Укажите своё имя.
7. Введите имя сервера, например `student-server`.
8. Создайте имя пользователя, например `student`.
9. Придумайте пароль и запомните его.
10. На экране настройки SSH отметьте **Install OpenSSH server**.
11. Дополнительные серверные пакеты устанавливать не нужно.
12. Дождитесь завершения установки.
13. Выберите **Reboot Now**.

После перезапуска войдите с созданным именем пользователя и паролем.

При вводе пароля в Ubuntu символы не отображаются даже точками. Это нормально: введите пароль и нажмите `Enter`.

## Шаг 4. Настройте сетевые адаптеры

Выключите виртуальную машину:

```bash
sudo poweroff
```

Дождитесь, пока окно виртуальной машины закроется.

1. Выберите виртуальную машину в VirtualBox.
2. Нажмите **Настроить**.
3. Откройте раздел **Сеть**.
4. Выберите **Адаптер 1**.
5. Установите флажок **Включить сетевой адаптер**.
6. В поле **Тип подключения** выберите **NAT**.
7. Выберите **Адаптер 2**.
8. Установите флажок **Включить сетевой адаптер**.
9. В поле **Тип подключения** выберите **Виртуальный адаптер хоста**.
10. В поле имени выберите адаптер VirtualBox, созданный на первом шаге.
11. Убедитесь, что установлен флажок **Кабель подключён**.
12. Нажмите **ОК**.
13. Запустите Ubuntu.

## Шаг 5. Узнайте IP-адрес сервера

После входа в Ubuntu выполните:

```bash
ip -br address
```

Команда показывает сетевые интерфейсы и их адреса. Пример:

```text
lo               UNKNOWN        127.0.0.1/8
enp0s3           UP             10.0.2.15/24
enp0s8           UP             192.168.56.101/24
```

Здесь:

- `lo` — внутренний интерфейс самой Ubuntu;
- `enp0s3` — NAT для выхода в интернет;
- `enp0s8` — сеть между Ubuntu и Windows.

Нужен адрес, который начинается с `192.168.56`. В примере это `192.168.56.101`.

Запишите свой адрес. Во всех следующих командах вместо адреса из примера используйте адрес своей Ubuntu.

Проверьте доступ в интернет:

```bash
ping -c 4 8.8.8.8
```

Проверьте работу DNS:

```bash
ping -c 4 ubuntu.com
```

Если обе команды получили ответы, интернет и DNS работают.

Теперь откройте в Windows **PowerShell** или **Терминал**:

1. Нажмите кнопку **Пуск**.
2. Введите `PowerShell`.
3. Откройте найденное приложение.

Проверьте доступность Ubuntu:

```powershell
ping 192.168.56.101
```

Замените адрес на адрес своей Ubuntu.

## Шаг 6. Подключитесь к серверу по SSH

Если OpenSSH не был выбран при установке Ubuntu, установите его в консоли виртуальной машины:

```bash
sudo apt update
sudo apt install openssh-server -y
```

Запустите службу SSH и включите её автоматический запуск:

```bash
sudo systemctl enable --now ssh
```

Проверьте состояние:

```bash
systemctl status ssh
```

В строке состояния должно быть написано `active (running)`.

Чтобы выйти из просмотра состояния, нажмите `Q`.

В PowerShell на Windows выполните:

```powershell
ssh student@192.168.56.101
```

Замените:

- `student` на своё имя пользователя Ubuntu;
- `192.168.56.101` на IP-адрес своей Ubuntu.

При первом подключении появится вопрос:

```text
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Введите:

```text
yes
```

Затем введите пароль пользователя Ubuntu.

Если подключение выполнено, в начале строки появится имя пользователя и сервера, например:

```text
student@student-server:~$
```

Все следующие команды можно выполнять через SSH из Windows.

## Шаг 7. Установите Nginx

Обновите информацию о доступных пакетах:

```bash
sudo apt update
```

Установите Nginx и OpenSSL:

```bash
sudo apt install nginx openssl -y
```

Запустите Nginx и добавьте его в автоматический запуск:

```bash
sudo systemctl enable --now nginx
```

Проверьте состояние:

```bash
systemctl status nginx
```

Должно отображаться `active (running)`. Нажмите `Q`, чтобы выйти.

Проверьте ответ сервера внутри Ubuntu:

```bash
curl -I http://localhost
```

Первая строка ответа должна выглядеть примерно так:

```text
HTTP/1.1 200 OK
```

Это означает, что Nginx работает и вернул успешный ответ.

## Шаг 9. Настройте HTTP-сайт

Nginx хранит настройки сайтов в `/etc/nginx/sites-available`.

Создайте файл настройки:

```bash
sudo nano /etc/nginx/sites-available/student-site
```

Добавьте:

```nginx
server {
    listen 80;
    listen [::]:80;

    server_name _;

    root /var/www/student-site;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

Что означает каждая настройка:

| Настройка | Объяснение |
| --- | --- |
| `listen 80` | Принимать HTTP-подключения на порту 80 |
| `server_name _` | Принимать запросы с любым именем или IP-адресом |
| `root` | Папка, в которой находятся файлы сайта |
| `index index.html` | Файл, который нужно открыть как главную страницу |
| `location /` | Правила обработки запросов к сайту |
| `try_files` | Проверить существование запрошенного файла, иначе вернуть ошибку 404 |

Сохраните файл и закройте `nano`.

Включите созданный сайт:

```bash
sudo ln -s /etc/nginx/sites-available/student-site /etc/nginx/sites-enabled/student-site
```

Отключите стандартную страницу Nginx:

```bash
sudo unlink /etc/nginx/sites-enabled/default
```

Проверьте настройки:

```bash
sudo nginx -t
```

Успешный результат заканчивается строками:

```text
syntax is ok
test is successful
```

Примените изменения:

```bash
sudo systemctl reload nginx
```

`reload` заставляет Nginx перечитать настройки без полной остановки сервера.

## Шаг 10. Проверьте HTTP

Откройте браузер в Windows и введите IP-адрес Ubuntu:

```text
http://192.168.56.101
```

Замените адрес на свой.

Должна открыться созданная HTML-страница.

Обязательно укажите `http://`. Иначе браузер может автоматически попытаться открыть HTTPS раньше, чем оно настроено.

Проверьте заголовки через Ubuntu:

```bash
curl -I http://192.168.56.101
```

В ответе должен быть код `200 OK`.

## Шаг 11. Создайте сертификат

Создайте закрытый ключ и самоподписанный сертификат. В следующей команде два раза замените `192.168.56.101` на IP-адрес своей Ubuntu.

```bash
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/student-site.key \
  -out /etc/ssl/certs/student-site.crt \
  -subj "/C=RU/ST=Samara/L=Samara/O=PGK/OU=Students/CN=192.168.56.101" \
  -addext "subjectAltName=IP:192.168.56.101"
```

Команда может занимать несколько секунд.

Что было создано:

| Файл | Назначение |
| --- | --- |
| `/etc/ssl/private/student-site.key` | Закрытый ключ сервера. Его нельзя передавать другим людям |
| `/etc/ssl/certs/student-site.crt` | Сертификат, который сервер показывает клиенту |

Параметры команды:

| Параметр | Объяснение |
| --- | --- |
| `req -x509` | Создать самоподписанный сертификат |
| `-nodes` | Не запрашивать пароль при запуске Nginx |
| `-days 365` | Сертификат действует 365 дней |
| `-newkey rsa:2048` | Создать новый закрытый RSA-ключ длиной 2048 бит |
| `-keyout` | Куда сохранить закрытый ключ |
| `-out` | Куда сохранить сертификат |
| `-subj` | Основные сведения сертификата |
| `subjectAltName` | IP-адрес, для которого выпущен сертификат |

Проверьте сведения сертификата:

```bash
sudo openssl x509 -in /etc/ssl/certs/student-site.crt -noout -subject -issuer -dates -ext subjectAltName
```

В результате должен отображаться IP-адрес вашей Ubuntu.

## Шаг 12. Настройте HTTPS

Снова откройте настройку сайта:

```bash
sudo nano /etc/nginx/sites-available/student-site
```

Удалите старое содержимое и вставьте:

```nginx
server {
    listen 80;
    listen [::]:80;

    server_name _;

    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;

    server_name _;

    ssl_certificate /etc/ssl/certs/student-site.crt;
    ssl_certificate_key /etc/ssl/private/student-site.key;

    root /var/www/student-site;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

Теперь в файле находятся два блока `server`.

Первый блок:

- принимает HTTP-запросы на порту `80`;
- возвращает код `301`;
- перенаправляет браузер на такой же адрес, но с `https://`.

Второй блок:

- принимает HTTPS-подключения на порту `443`;
- включает TLS с помощью параметра `ssl`;
- указывает путь к сертификату;
- указывает путь к закрытому ключу;
- отдаёт HTML-файлы из папки сайта.

Проверьте настройки:

```bash
sudo nginx -t
```

Если проверка успешна, примените изменения:

```bash
sudo systemctl reload nginx
```

Посмотрите, какие порты слушает Nginx:

```bash
sudo ss -lntp | grep nginx
```

В результате должны присутствовать порты `80` и `443`.

## Шаг 13. Проверьте HTTPS

Сначала проверьте перенаправление:

```bash
curl -I http://192.168.56.101
```

Замените адрес на свой.

В ответе должны присутствовать:

```text
HTTP/1.1 301 Moved Permanently
Location: https://192.168.56.101/
```

Код `301` сообщает браузеру, что нужно перейти на другой адрес.

Теперь проверьте HTTPS:

```bash
curl -k -I https://192.168.56.101
```

Параметр `-k` разрешает `curl` подключиться к серверу с самоподписанным сертификатом. Ожидаемый ответ:

```text
HTTP/1.1 200 OK
```

Откройте в браузере Windows:

```text
https://192.168.56.101
```

Браузер покажет предупреждение о сертификате. Это происходит не из-за отсутствия шифрования, а из-за того, что сертификат создан вами и не подписан доверенным центром сертификации.

Для продолжения в учебной локальной сети:

1. Нажмите **Дополнительные**.
2. Выберите продолжение перехода на сайт.

Название кнопки зависит от браузера. Не обходите такое предупреждение на неизвестных сайтах в интернете.

После продолжения должна открыться ваша HTML-страница.

Теперь введите адрес с HTTP:

```text
http://192.168.56.101
```

Браузер должен автоматически перейти на:

```text
https://192.168.56.101
```

## Шаг 14. Разрешите подключения в UFW

UFW — программа для управления межсетевым экраном Ubuntu. Межсетевой экран решает, какие входящие подключения разрешены.

Сначала разрешите SSH, чтобы не потерять удалённое подключение:

```bash
sudo ufw allow OpenSSH
```

Разрешите HTTP и HTTPS:

```bash
sudo ufw allow "Nginx Full"
```

Включите UFW:

```bash
sudo ufw enable
```

На вопрос о продолжении введите `y` и нажмите `Enter`.

Проверьте правила:

```bash
sudo ufw status
```

Должны быть разрешены:

```text
OpenSSH
Nginx Full
```

После включения UFW ещё раз проверьте SSH и сайт из Windows.

Работа выполнена, если соблюдены все условия:

- Ubuntu Server запускается в VirtualBox;

- Windows видит Ubuntu через виртуальный адаптер хоста;
- подключение из Windows по SSH работает;
- Nginx запущен;
- на сайте указаны ФИО и группа студента;
- `http://IP_СЕРВЕРА` перенаправляет на HTTPS;

Полезные команды для демонстрации преподавателю:

В двух последних командах используйте IP-адрес своей Ubuntu.

## Частые ошибки

### Windows не видит Ubuntu

Проверьте:

1. В VirtualBox включён **Адаптер 2**.
2. Выбран режим **Виртуальный адаптер хоста**.
3. Установлен флажок **Кабель подключён**.
4. Команда `ip -br address` показывает адрес `192.168.56.x`.
5. Вы используете именно этот адрес, а не адрес NAT `10.0.2.15`.

### Команда SSH не подключается

Проверьте службу:

```bash
sudo systemctl status ssh
```

Проверьте порт:

```bash
sudo ss -lntp | grep :22
```

Проверьте, разрешён ли SSH:

```bash
sudo ufw status
```

### В браузере открывается стандартная страница Nginx

Проверьте, какие сайты включены:

```bash
ls -l /etc/nginx/sites-enabled
```

В списке должен быть `student-site`, а `default` должен отсутствовать.

### После изменения HTML отображается старая страница

Обновите страницу без использования кэша:

```text
Ctrl + F5
```

### Nginx сообщает об ошибке в настройках

Выполните:

```bash
sudo nginx -t
```

Команда укажет файл и номер строки с ошибкой. Обычно причина — пропущенная точка с запятой `;`, лишний символ или неправильный путь к сертификату.

После исправления снова выполните:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### HTTPS не открывается

Проверьте наличие файлов:

```bash
sudo ls -l /etc/ssl/certs/student-site.crt
sudo ls -l /etc/ssl/private/student-site.key
```

Проверьте порт `443`:

```bash
sudo ss -lntp | grep :443
```

Проверьте HTTPS внутри Ubuntu:

```bash
curl -k -I https://localhost
```

### Браузер предупреждает, что подключение небезопасно

Для этой работы это нормально. Соединение шифруется, но сертификат самоподписанный и не входит в список доверенных сертификатов Windows.

### В сертификате указан неправильный IP-адрес

Создайте сертификат заново, указав правильный IP в `CN` и `subjectAltName`, затем перезагрузите Nginx:

```bash
sudo systemctl reload nginx
```

## Что нужно понимать после выполнения

- SSH используется для безопасного удалённого управления сервером.
- HTTP определяет обмен запросами и ответами между браузером и веб-сервером.
- Обычный HTTP не шифрует данные.
- HTTPS использует TLS для защиты соединения.
- HTTP обычно работает на порту `80`, HTTPS — на порту `443`, SSH — на порту `22`.
- Nginx принимает запросы и возвращает браузеру файлы сайта.
- Сертификат связывает адрес сервера с открытым ключом.
- Самоподписанный сертификат шифрует соединение, но не является доверенным для браузера.
- Перенаправление с HTTP на HTTPS выполняется ответом с кодом `301`.
